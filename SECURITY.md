# Security policy

## Reporting sensitive publication or verification failures

Do not disclose credentials, private keys, personal identifiers, unpublished record material, or a
working exploit in a public issue.

Use GitHub private vulnerability reporting for this repository. Include the affected path and
commit, the category of material exposed or check bypassed, and enough non-sensitive information to
reproduce the problem safely.

If private vulnerability reporting is unavailable, contact the repository owner through an
established private channel and reference this policy without copying the sensitive material.

High-priority reports include publication of excluded control-plane fields, artifact-hash bypasses,
record truncation presented as current, signature or replay failures, and discrepancies between a
published checkpoint and its represented record cut.
